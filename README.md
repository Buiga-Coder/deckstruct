# Deckstruct - Генератор презентаций по шаблону

Общий интеграционный проект команды: веб-интерфейс создания презентаций по PPTX-шаблону.

**Текущее состояние: демонстрационный фронт.** Регистрация, шаблоны и генерация работают через MockBackend в браузере. Настоящая генерация PPTX, серверная авторизация и подключение парсера ещё не реализованы. Не используйте реальные пароли или конфиденциальные материалы в демо.

## Запуск

Требуется Docker Compose. В корне проекта:

```sh
docker compose up -d --wait
```

Открыть http://localhost:8081. Проверка доступности: `/healthz`. Пока backend не подключён, `/api/*` возвращает JSON и HTTP 503.

Для просмотра дизайна без Docker можно открыть `frontend/index.html` в браузере. Для проверки JavaScript: `node scripts/check-frontend.mjs`.

## Организация

- `frontend/index.html` — исходный P5.html с обозначением деморежима.
- `infra/` и `compose.yml` — отдельный контейнер фронта и лимиты ресурсов.
- `services/` — место для подключения работ разработчиков; договорённости в `docs/integration.md`.
- `docs/operations.md` — обновление и откат на сервере.
- `.github/workflows/check.yml` — автоматическая проверка синтаксиса JS, Compose и HTTP на push/PR.

## Работа команды

`main` — проверенная общая сборка. Каждый делает изменения в отдельной ветке: `feature/parser`, `feature/generation`, `design/frontend`. Объединять через pull request; лидер проверяет CI и основной пользовательский сценарий. Эти правила — договорённость команды, защита ветки ещё не настроена.

Дизайнеры меняют `frontend/`, разработчики подключают свои модули в `services/`, лидер отвечает за `infra/`, контракт API и выпуск сборки. Перед крупной заменой HTML согласовать изменения API, чтобы не потерять интеграцию.

Автоматический деплой пока не включён: сначала подключить backend и определить стабильный сценарий проверки. CI подготовлен, его первый запуск проверяется после публикации репозитория.
