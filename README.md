**Текущее состояние: рабочий интеграционный прототип.** Регистрация, серверная авторизация, анализ PPTX и генерация трёх вариантов презентации подключены. Сервис использует Express, SQLite, отдельный parser и VLM через Polza AI. Не добавляйте ключи и пароли в Git.

## Возможности

- регистрация, вход, JWT-сессии и роли `user`/`admin`;
- загрузка PPTX-шаблонов до 50 МБ;
- анализ слайдов с превью, палитрой, типографикой, сеткой и токенами;
- генерация трёх вариантов PPTX из шаблона и ZIP с контентом;
- отдельное скачивание каждого варианта;
- SQLite с WAL и изоляция данных по владельцу.

## Архитектура

```text
Браузер → Caddy/frontend → Express API → SQLite
                                  ↓
                              parser :8765
                                  ↓
                       Polza AI / Qwen3 VL 32B
                                  ↓
                     presentation-builder → PPTX
```

`frontend/` содержит интерфейс и админ-панель, `services/api/` — API и авторизацию, `services/parser/` — очередь анализа и генерацию, `vendor/presentation-builder/` — генератор PPTX.

## Запуск

Открыть http://localhost:8081. Проверка доступности: `/healthz`. API и parser запускаются отдельными контейнерами и проверяются healthcheck-ами.


## Конфигурация

Секреты задаются через `.env` или внешний `DECKSTRUCT_ENV_FILE` и не коммитятся:

```dotenv
JWT_SECRET=длинная-случайная-строка
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=изменить-перед-запуском
VLM_API_KEY=ключ-провайдера
VLM_API_BASE_URL=https://api.polza.ai/v1
VLM_MODEL=qwen/qwen3-vl-32b-instruct
```

На сервере Deckstruct развёрнут отдельным Compose-проектом и не переиспользует контейнеры VK-бота.

## Сценарий демонстрации

1. Войти или зарегистрироваться.
2. Загрузить PPTX-шаблон и дождаться анализа.
3. Выбрать шаблон, указать описание и загрузить ZIP с материалами.
4. Запустить генерацию и скачать вариант 1, 2 или 3.

Неполный шаблон можно использовать в режиме продолжения по валидным слайдам. Ошибка одного слайда не останавливает остальные.

## Ограничения текущей версии

Качество зависит от VLM и доступности Polza AI. Сложные master-объекты, диаграммы и нестандартные элементы могут получить статус «требуется проверка». Генератор создаёт редактируемые PPTX по найденным слотам. Email-подтверждение, OAuth, сброс пароля, rate limiting и аудит действий ещё не подключены.

## Проверки

```sh
docker compose config
node scripts/check-frontend.mjs
python -m unittest discover -s tests -p 'test_*.py'
node tests/api-integration.cjs
```

GitHub Actions запускает проверки для push и pull request. `main` — интеграционная ветка; изменения рекомендуется вносить через отдельные ветки и pull request.

## Организация

- `frontend/index.html` — пользовательский интерфейс создания презентаций.
- `infra/` и `compose.yml` — отдельный контейнер фронта и лимиты ресурсов.
- `services/api/` — Express API, JWT, SQLite, загрузки и выдача PPTX.
- `services/parser/` — анализ шаблонов, очередь, статусы и генерация вариантов.
- `vendor/presentation-builder/` — подключённый генератор редактируемых PPTX.
- `docs/operations.md` — обновление и откат на сервере.

CI проверяет синтаксис, Compose, API-контракт, анализатор и генератор на push и pull request. Перед демонстрацией рекомендуется выполнить `docker compose up -d --build --wait`, затем проверить `/healthz` и основной сценарий генерации.
