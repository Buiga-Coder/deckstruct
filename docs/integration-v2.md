# Интеграция 28.09.2026

Источники:
- Фронт и Express/SQLite API: https://github.com/molkarden/destrick, commit `b061689`.
- Парсер: https://github.com/daniilboriskin21-eng/pptx-template-parser, commit `f5c84b9`.

Снимок парсера в `vendor/pptx-template-parser` сохранён без изменений. Большой тестовый PPTX и отчёт об исследовании данных не включены. Адаптер в `services/parser/bridge.py`; согласовывать последующие обновления со схемой API. Backend в `services/api` сохраняет базовую схему SQLite и контракты фронта, добавляя права доступа к задачам парсера. Исходные upstream-репозитории не изменены.

## Схема

Браузер → Caddy → Express/SQLite → приватный Python-парсер → LibreOffice/Poppler → Polza AI → Qwen3 VL 32B.

Внешние порты API и парсера не публикуются. Парсер использует одну очередь с одним worker, сохраняет пакет и статус на диске. Веб-API связывает `template_id` с `owner_id` и `parser_job_id`. Браузер не получает сервисный токен или ключ Polza.

SQLite и загрузки: `/opt/deckstruct/shared/api`; пакеты парсера: `/opt/deckstruct/shared/parser`. Они переживают обновление контейнеров. Секреты: `/opt/deckstruct/shared/secrets/app.env`, права 600. Администратор создаётся из `ADMIN_EMAIL` и `ADMIN_PASSWORD_HASH`; публичная регистрация всегда создаёт пользователя. Пароль и ключ не входят в Git.

Модель: `qwen/qwen3-vl-32b-instruct`, адрес `https://polza.ai/api/v1`. Ключ: `VLM_API_KEY`. Совместимость конкретного провайдера проверяется реальным слайдом. По умолчанию сохранена пауза 10 секунд между запросами; меняется `VLM_SLIDE_DELAY`. Секреты читаются при старте контейнера — после изменения env выполнить `up -d --force-recreate parser`.

## Проверяемые API

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/capabilities` | Доступность парсера и настройки модели; `generation:false` |
| POST | `/api/templates` | Multipart `file`, ответ 202 с template id и состоянием |
| GET | `/api/templates/:id/analysis` | Реальный статус, прогресс, структура и семантика |
| POST | `/api/templates/:id/analyze` | Отправить сохранённый шаблон или продолжить прерванную задачу |
| GET | `/api/templates/:id/previews/s1.png` | Авторизованное превью |
| GET | `/api/templates/:id/package` | Неизменяемый ZIP результата парсера |
| GET/PATCH | `/api/design-systems/:id` | Пользовательские правки отдельно от исходных фактов |
| POST | `/api/decks` | Пока 503 `GENERATOR_NOT_CONNECTED` |

Статусы: queued, extracting, rendering, analyzing, exporting, completed, partial, failed, interrupted. Без ключа после извлечения и рендера — awaiting_configuration. После настройки ключа нажать «Продолжить анализ». При сбое отправки — submission_failed: шаблон сохранён, можно повторить. Частичный результат не обозначается как полностью готовый.

XML-цвета, шрифты, размеры и макеты реальные, но наследование всех стилей не разрешено. Не выдаём выдуманные confidence, сетку и токены. Семантические компоненты выводятся только из ответа парсера. Пользовательские JSON-правки сохраняются отдельно и пока не применяются генератором. Галерея содержит демонстрационные дизайны; для работы загружается собственный PPTX.

## Подключение генератора третьего разработчика

Предлагаемый вход: авторизованный `template_id`, сохранённые файлы контента, настройки языка/числа слайдов. Backend сам получает `parser_job_id`, неизменяемый `version` и `archive_sha256`; генератор читает ZIP по приватному API с сервисным токеном и проверяет хэш. Не доверять присланным браузером путям или произвольным URL.

Предлагаемый выход фоновой задачи: `deck_id`, queued/running/completed/failed, путь готового PPTX внутри приватного хранилища, число слайдов и диагностические сообщения. Скачивание — только после completed и проверки owner_id. До подключения реального генератора загрузка материалов в UI отключена, usage не расходуется, мок-PPTX не выдаётся. Контракт генератора требуется согласовать с его автором.

## Развёртывание и откат

Применять из каталога нового release, сохранив предыдущий путь и резервную копию SQLite:

```sh
export DECKSTRUCT_ENV_FILE=/opt/deckstruct/shared/secrets/app.env
export DECKSTRUCT_DATA_DIR=/opt/deckstruct/shared
export RELEASE_TAG=unique-release-tag
docker compose -p deckstruct build
docker compose -p deckstruct up -d --wait --wait-timeout 120
```

После проверок обновить `current`. Для отката выбрать предыдущий release и поднять его Compose; новые API/parser остановить отдельно, если предыдущий release содержит только фронт. Не удалять shared. Новые миграции добавляют столбцы и не удаляют пользовательские данные. Резервная копия активной SQLite делается через `better-sqlite3.backup`, а не копированием одного .db при WAL.

Лимиты: frontend 64 МБ, API 192 МБ, parser 704 МБ (+128 МБ swap), последовательный анализ. На тяжёлом PPTX возможен OOM парсера — после рестарта статус станет interrupted. Хост с 2 ГБ не рассчитан на массовую параллельную обработку. Лимиты загрузок: 50 МБ/файл, 30 шаблонов и ориентир 300 МБ на пользователя, 1 ГБ исходников суммарно. Парсер сохраняет старые snapshots для восстановления даже после удаления записи в UI; они доступны только на сервере. До широкого использования добавить согласованную политику очистки snapshots и пагинацию админки. Проверка свободного диска останавливает приём новых задач при остатке менее 2 ГБ.

Тесты API используют временную БД и имитацию парсера без платных запросов: `node tests/api-integration.cjs`. Реальный Linux-рендер проверяется upstream-тестами. Живой вызов модели отдельно проверять на коротком синтетическом слайде, без пользовательских документов.
