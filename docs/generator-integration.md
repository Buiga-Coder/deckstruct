# Генерация и диагностика — 29 сентября 2026

Генератор: `UTo4ka-etxt/ai-presentation-template-builder`, исходная ревизия `dd56c7c607d7086ecac3329109f403f44a4cf80e`, код в `vendor/presentation-builder`. Небольшая локальная правка planner проверяет типы текста и пути изображений из материалов. Отдельная публичная FastAPI-панель разработчика не запускается: используем общий Express, роли и SQLite.

`services/parser/generation.py` читает конкретную неизменяемую версию экспорта парсера с проверкой SHA256; повторный разбор исходного шаблона не выполняется. Генератор и парсер используют общую последовательную очередь (ёмкость 4). В памяти одновременно не выполняются тяжёлый рендер и сборка. Оба работают с тем же ключом Polza и той же Qwen3 VL; новые ключи и провайдеры не нужны.

Пользователь выбирает шаблон, ZIP материалов, задачу, 3–20 слайдов. Результат — три варианта PPTX. Если анализ частичный, требуется явно разрешить использовать только валидные слайды. Генератор не меняет общие master/layout-объекты и данные диаграмм; эти слоты исключаются из предложений модели. JSON-правки дизайн-системы пока не применяются. Аудит проверяет структуру файла, а не визуальное отсутствие всех переполнений — итог нужно просмотреть.

API:
- `POST /api/decks`: multipart `template_id`, `title`, `brief`, `slide_count`, `content` (ZIP), необязательное `allow_partial=true`. Возвращает 202, id задания.
- `GET /api/decks/:id`: status/percent/message/variants.
- `POST /api/decks/:id/resume`: продолжение после ошибки или рестарта; готовые планы повторно не запрашиваются.
- `GET /api/decks/:id/download?variant=1|2|3`: только владелец, только после полного успеха.

Состояния и планы хранятся в `shared/parser/generations`. При рестарте незавершённые задания помечаются interrupted. Учёт usage производится один раз за завершённое задание, не за каждый опрос/вариант. Worker API приватный, с сервисным токеном; внешний клиент не выбирает серверные пути. ZIP ограничен по числу файлов, распакованному объёму и вложенным Office-архивам; проверяется traversal. Приватный error.json хранит диагностику с удалением ключа; в браузер не отправляются пути/сырые ответы провайдера.

Обнаружено на сервере:
- 55/55 PNG успешно созданы Linux. Пакет остановился на API timeout слайда s25; 7 предыдущих результатов не прошли валидацию модели.
- Другие частичные результаты содержали пересечение текстовых слотов, несуществующие ID и пропущенные объекты мастера. Это ошибки ответа модели, не потеря файлов рендерером.
- Три больших шаблона не прошли рендер; контейнер имел OOMKilled=true и накопленные дочерние zombie-процессы.
- UTF-8 имена multipart декодировались библиотекой как latin1. Новые имена корректируются; сохранённые названия мигрируются точным обратимым преобразованием.

Изменения: init-процесс для сбора дочерних процессов, память worker 896 МиБ (+384 МиБ swap), превью 1000 px, тайм-аут рендера зависит от числа слайдов (до 30 минут). Межслайдовая пауза 1 секунда вместо 10, 429 по-прежнему уважает Retry-After. Единичный timeout не повторяется автоматически (ответ мог быть оплачен), но обработка идёт дальше; три подряд временных сбоя останавливают пакет. Ошибки авторизации/баланса/лимитов останавливают его сразу. Вторая попытка исправления разметки моделью разрешена. Готовые семантики при продолжении сохраняются.

Старая документация integration-v2.md описывает состояние до подключения генератора. Актуальные лимиты — в compose.yml; инструкция безопасного развёртывания и отката прежняя. Перед обновлением сохранять SQLite через backup API и предыдущий release. Не перезапускать проект ipmkn-start.
